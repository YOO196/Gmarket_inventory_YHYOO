# 전체 흐름·웹 앱 정의

## 1. 문서 기준
| 구분 | 적용 |
|---|---|
| 실제 사례 | B마트 공식 WMS(창고·재고 관리)·OMS(주문·출고 관리)·목포 PPC(피킹·포장센터) 운영을 우선. 쿠팡은 참고 사례 |
| 프로젝트 정의 | 사용자 문서 채번·원문 요구·센터 구역·권한 구성 |
| 정책 미정 | 업체 공개 근거 없는 계약·승인·시간·비율·원장 차감 사건 |

- 상세 근거·게시시점은 [실사례 조사](14_미정정책_쿠팡_B마트_실사례조사.md).
- 공통 운영 웹·A~H·문서번호는 실제 B마트 내부 구현으로 단정하지 않음.

## 2. 센터별 전체 흐름
```mermaid
flowchart TD
    S[공급사] --> P[PO(구매발주) 발주·ASN(공급사 납품예정) 납품예정]
    P --> R[DC(중앙 물류센터) 공급사 입고 RCV(입고·검수)·검수]
    R --> D[DC(중앙 물류센터) 보관 재고]
    D --> T[TRF(센터 간 이송) 이관·위치 할당]
    T --> O[TOUT(이송 출발) 출발·이동중]
    O --> I[PPC(피킹·포장센터) TIN(이송 도착) 도착·검수]
    I --> K[PPC(피킹·포장센터) 적치·판매 적합 현물]
    K --> V[현재·예정·할당 재고 판단]
    C[고객 바로배달·예약 주문] --> V
    V --> H[SHP(출하) 출하 단위·출고 요청]
    H --> W[TSK(작업 식별자) 피킹·PKG(실물 포장 식별자) 포장]
    H --> B[준비예정시각 기반 배달 요청]
    W --> E[품질 유지 대기·준비완료]
    E --> F[유효 포장 확인·HOV(기사 인계) 인계]
    B --> F
    F --> L[고객 배송]
```

| 구간 | 담당 | 핵심 차이 |
|---|---|---|
| 공급사→DC(중앙 물류센터) | 구매·입고·정산 | 납품 검수·매입 검토 |
| DC(중앙 물류센터)→PPC(피킹·포장센터) | DC(중앙 물류센터)·운송·PPC(피킹·포장센터) | 이관·할당·부분 도착. 신규 매입과 구분 |
| PPC(피킹·포장센터)→고객 | 주문·출고·라이더 | 주문 피킹·포장·인계 |

- DC(중앙 물류센터)와 PPC(피킹·포장센터) 모두 재고 보유. PPC(피킹·포장센터)의 별도 예비보관구역은 공간에 따라 선택.
- 품질·반품·폐기, 실사·조정, 작업배정은 위 과정과 연결.
- 입고·검수 화면은 두 센터에서 공통 사용 가능. 근거 문서 RCV(입고·검수)/TIN(이송 도착)은 구분.

근거: [B마트 WMS DC→PPC](https://techblog.woowahan.com/17416/), [B마트 OMS 주문·출고](https://techblog.woowahan.com/22263/).

## 3. 웹·앱 구성
| 서비스 | 사용자 | 기능·범위 |
|---|---|---|
| 공통 운영 웹 | 본사·DC(중앙 물류센터)·PPC(피킹·포장센터) 관리자 | 공통 재고·품질·실사·이관·작업 관리. 센터별 첫 화면·메뉴 |
| DC(중앙 물류센터) 작업 화면 | DC(중앙 물류센터) 작업자 | 공급사 입고·보관·PPC(피킹·포장센터)별 집품·상차 |
| PPC(피킹·포장센터) PDA(현장 작업 단말) 화면 | PPC(피킹·포장센터) 작업자 | 이관 도착·적치·보충·고객 피킹·포장·인계 |
| 공급사 포털 | 공급사 | 등록·상품등록 신청·발주 응답·ASN(공급사 납품예정)·협의·정산 |
| 기사 기능 | 운송기사·라이더 | 각 배정·인계·지연. 고객 앱과 별도 역할 |
| 고객 앱 연계 | 고객 | 즉시/예약 주문·배송 약속·주문 변경 안내 |
| 자동처리 모듈 | 시스템 | 재고·현장 여건 기반 판단·알림·추적 |

- 공통 웹은 프로젝트 구성 권고. 실제 업체 웹 구조 미확인.
- 관리자 웹·PDA(현장 작업 단말) 통합 제공은 기존 검토 유지. 화면 형식과 승인 권한은 별개.
- 권한 = 접근센터 × 직무 × 행위 × 배정작업 × 승인조건.
- ID는 식별자. 화면 메뉴뿐 아니라 서버에서 센터·문서·행위 권한 확인.
- 기사 별도 앱 구축·기존 서비스 연계 여부는 미정.

## 4. 재고 관제·판매 판단
| 개념 | 집계·판단 |
|---|---|
| 센터 현물 | DC(중앙 물류센터)·PPC(피킹·포장센터) 위치별 관리 수량. 격리 포함 |
| 센터 간 이동중 | 출발했으나 도착·조정으로 해소되지 않은 물량 |
| 전체 관리 현물 | DC(중앙 물류센터) + PPC(피킹·포장센터) + 센터 간 이동중. 같은 물량 한 번 집계 |
| 가용/즉시 판매가능 | 대상 PPC(피킹·포장센터)의 판매 적합 현물에서 예약·할당 제외 |
| 예정재고 | 미래 입고 약속. 현재 현물에 합산 금지 |
| 예약 가능 | 예정·현재·확보 물량과 배송 가능시각을 함께 판단 |

- 예약·격리는 재고의 관계·상태. 전체 현물에 더할 별도 물량 아님.
- DC(중앙 물류센터)에 재고가 있어도 해당 PPC(피킹·포장센터)의 즉시 판매가능으로 바로 표시하지 않음.
- 센터 관리 현물과 소유권·회계 재고·고객 배송중 집계 범위는 구분.

## 5. 예약·출고 제어
- B마트 공개 사례: 입고예정 재고 예약 판매·현장 여유 시간 작업 분산.
- 고객 수령시간과 작업 시작시간 구분. 출고요청·배달요청 분리.
- 작업 여유·품질 보존 구간에 따라 처리. 재고부족 주문의 SKIP 사례 있음.
- 마지막 시점 부족 시 고객 연락·취소 기준은 미확인.
- 포장완료·픽업준비완료·기사인계·재고원장 반영은 별도 사건.
- 실제 원장 차감 시점·슬롯 판매 상한·대기시간은 [미정 정책](12_운영정책_지침안.md).

## 6. 예외 처리 연결
| 발견 | 조치 경로 — 프로젝트 흐름 |
|---|---|
| 발주 변경·미납품 | PCH(발주 변경 요청)·PCN(발주 잔량 취소)·ASN(공급사 납품예정)·공급사 협의 |
| 검수 파손·수량 차이 | 실제 수량·품질 상태 기록 → QLT(품질 격리)·계약 검토 |
| 이관 부족 | TIN(이송 도착) 실제 도착·잔량 유지 → 조사·승인 조정 |
| 위치 오류·용량 부족 | 차단·재배정·실제 이동 기록 |
| 실사 차이 | 재계수·변동 대조 → ADJ(재고 조정) |
| 피킹 결품 | EXC(결품·대체 처리)·고객 결정 → OCN(고객 주문 취소)/RFD(환불)·예약 변경 |
| 훼손 포장 | 새 PKG(실물 포장 식별자)·기존 무효·교체 관계 |
| 전달 누락 | 전체 인계완료 보류·실제 전달 상태 추적 |
| 통신 오류 | 임시저장·결과 조회·같은 요청 ID 재전송 |

## 7. 문서·데이터 연결
- PO(구매발주) → 여러 ASN(공급사 납품예정)·RCV(입고·검수). 원문서와 내부 고유 상품행까지 연결.
- TRF(센터 간 이송) → 할당 항목 → TOUT(이송 출발) → 실제 도착별 TIN(이송 도착).
- ORD(고객 주문) → SHP(출하) → TSK(작업 식별자)·TOTE(재사용 운반 용기) 사용 이력 → PKG(실물 포장 식별자) → HOV(기사 인계).
- 품질 QLT(품질 격리) → RTV(공급사 반품) 또는 DSP(폐기). 실제 실행·재고 결과 연결.
- CNT(재고 실사) → 재계수·변동 대조 → ADJ(재고 조정).
- PUR(매입확정) → 확정 후 PJA(매입 조정). 내부 이관은 중복 매입 생성 금지.
- 번호 생성과 승인·확정·반영 분리. 번호·이력 보존·한 번만 반영.

상세: [사용자 채번 지침](00_ERP·WMS%20업무%20문서%20채번%20지침.md).

## 8. 추가 확인·미결정 정책
- Lot 구분·병합. 문서 채번은 이미 사용자 정의 있음.
- 상품별 잔여 소비기한·격리해제·마감할인 조건.
- 파손 매입·공급사 변경·취소·비용 조건.
- 사진 범위·보관기간·폐기 결재선.
- 실사 잠금·주기·조정 승인.
- 교대 인계·오프라인 허용 기능.
- 결품 무응답·대체·환불·부분출하.
- 원장 차감 사건·인계 증빙·부분인계.
- 슬롯 상한·접수마감·품질 대기한계.
