# DC(중앙 물류센터)·PPC(피킹·포장센터) 구역·위치번호·운영 웹 설계안

## 1. 정의·적용 범위
- DC(중앙 물류센터): 공급사 상품 입고·대량 보관·PPC(피킹·포장센터) 보충 출고를 담당하는 중앙 거점.
- PPC(피킹·포장센터): DC(중앙 물류센터) 보충 물량 입고·보관·고객 주문 피킹·포장·라이더 인계 거점.
- 두 센터 모두 재고 보유. PPC(피킹·포장센터)를 통과형 TC로 정의하지 않음. (재고 보관은 필요. 별도 예비보관실·B구역 물리 분리는 규모에 따라 선택.)
- 아래 A~H 구역·번호 형식은 본 프로젝트 설계안. 실제 B마트 내부 구역명·코드로 확인된 내용이 아님.
- 구역은 업무 구분. 실제 층·방·벽의 개수와 동일하지 않음.
- 실제 평면·설비·작업량 확인 후 배치·면적 확정. 아래 흐름도는 업무 순서도.

## 2. DC(중앙 물류센터) 와 PPC(피킹·포장센터) 개념
| 구분 | **DC(중앙 물류센터) — 중앙 메가 물류센터** | **PPC(피킹·포장센터) — 도심형 주문 처리 거점** |
|---|---|---|
| 역할 | 공급사 상품을 받아 보관하고 지역 거점에 공급 | 고객 가까이에서 주문 상품을 준비 |
| 주요 입고 | 공급사 납품 | DC(중앙 물류센터)에서 보낸 보충 물량 |
| 주요 작업 | 입고 검수·분류·보관·재고관리·센터 이관 | 입고 검수·적치·재고 배치·피킹·포장 |
| 출고 대상 | PPC(피킹·포장센터) 등 다른 센터 | 고객 주문에 배정된 라이더 |
| 출고 기준 | 센터 보충·이관 요청 | 고객 주문·예약시간 |
| 재고 보유 | 보유 | 보유. 판매가능 재고로 관리 |

이런 구조에 따르는 이점은 다음과 같다.

1. DC(중앙 물류센터)에 통합 납품하는 것이 PPC(피킹·포장센터)에 개별 납품하는 것보다 공급사의 부담이 적다. 

2. 공간 압축적. 모든 센터를 대규모로 설계할 필요 없고, 중앙 물류센터(DC(중앙 물류센터)) 체계를 두고 각 PPC(피킹·포장센터)에 수요에 맞춰 공급.

3. DC(중앙 물류센터)는 박스 위주, PPC(피킹·포장센터)는 낱개 위주로 업무하며 피킹시설 전문화.

4. 중앙공급체계에서 PPC(피킹·포장센터)로 뻗어나가는 병렬구조는 PPC(피킹·포장센터) 거점을 늘리는 데에 용이함.

5. 재고 배분 유용성, 굳이 공급업체의 납품을 기다리지 않더라도. DC(중앙 물류센터)에서 수요 높은 PPC(피킹·포장센터)에 추가 물량 보충 가능.

6. 고객의 주문전 예상 수요만큼 PPC(피킹·포장센터)에 미리 배치해둠으로서 운송시간 단축.

## 4. 공통 구역 사전
| 구역 | 이름 | 공통 의미 |
|---|---|---|
| A | 입고·검수 | 도착·하차·검수·적치 대기 |
| B | 보관 | 정상 재고의 예비·대량 보관 |
| C | 집품·피킹 | 출고 대상 상품 집품 |
| D | 출하 준비 | 검품·포장·라벨·출하 단위 구성 |
| E | 출하 대기 | 준비 완료 상품·포장의 대기 |
| F | 상차·인계 | 차량 상차 또는 라이더 전달 |
| G | 품질 격리 | 파손·기한·품질 의심·회수 검토 |
| H | 반품·폐기 대기 | 처분 방식 결정 후 실행 대기 |

- 실사·보충은 업무 종류. 전용 물리 구역을 필수로 만들지 않음.
- 사무실·충전·휴게 공간은 시설정보 관리. 재고 적치 위치로 사용하지 않음.
- G·H는 정상 판매 동선과 구분. 격리·처분 대기도 필요한 보관온도 유지.

## 5. DC(중앙 물류센터) 구역 구성
| 구역 | 세부 구역 예 | 업무·입출력 | 다음 단계·조건 |
|---|---|---|---|
| A | A01 하차 / A02 검수 / A03 적치대기 | 공급사 도착·RCV(입고·검수) 검수·Lot 확인 | 정상 B, 이상 G |
| B | B01 상온 / B02 냉장 / B03 냉동 | 박스·팔레트 예비 재고 보관 | PPC(피킹·포장센터) 보충요청에 따라 C |
| C | C01 상온집품 / C02 냉장집품 / C03 냉동집품 | PPC(피킹·포장센터)별 할당·집품 | 품목·로트·수량 확인 후 D |
| D | D01 검품 / D02 출하구성 | PPC(피킹·포장센터) 목적지별 검품·운송단위 구성 | 목적지·수량 확인 후 E |
| E | E01 상온 / E02 냉장 / E03 냉동 | 노선·도착센터별 상차 대기 | 배차·보관조건 확인 후 F |
| F | F01 도크 / F02 도크 | 차량·이송·상차 확인 | TOUT(이송 출발) 확정·이동중 반영 |
| G | G01 상온 / G02 냉장 / G03 냉동 | 격리·재검수 | 해제 B 또는 처분 H |
| H | H01 반품 / H02 폐기 | RTV(공급사 반품)·DSP(폐기) 대상 실행 대기 | 실제 반출·폐기 확인 후 차감 |

- C 집품은 PPC(피킹·포장센터) 공급 목적. 고객 토트 피킹과 구분.
- 작은 DC(중앙 물류센터)는 B에서 직접 집품 가능. C 전용 선반 없이도 집품 작업은 유지.
- DC(중앙 물류센터) 고객 주문 처리·기사 인계는 현재 기본 범위 아님. 필요 시 별도 기능 활성화.

```text
공급사 → A 입고·검수 → B 보관 → C PPC(피킹·포장센터)별 집품 → D 출하 준비 → E 대기 → F 상차
              └─ 이상 → G 격리 → 재검수 적합: B / 처분 결정: H
```

## 6. PPC(피킹·포장센터) 구역 구성
| 구역 | 세부 구역 예 | 업무·입출력 | 다음 단계·조건 |
|---|---|---|---|
| A | A01 도착 / A02 검수 / A03 적치대기 | DC(중앙 물류센터) 물량 도착·TIN(이송 도착)·품질 확인 | 정상 B 또는 C, 이상 G |
| B | B01 상온 / B02 냉장 / B03 냉동 | 피킹선반 보충용 예비 재고 | MOV(센터 내부 이동·적치·보충) 보충으로 C |
| C | C01 상온 / C02 냉장 / C03 냉동 | 고객 주문별 낱개 피킹 | ORD(고객 주문)·TSK(작업 식별자)·TOTE(재사용 운반 용기) 확인 후 D |
| D | D01 검품 / D02 포장 | 주문 검품·온도별 포장·PKG(실물 포장 식별자) 라벨 | 전체 포장 확인 후 E |
| E | E01 상온 / E02 냉장 / E03 냉동 | 바로배달·예약 주문 대기 | 보관시간·온도·배차 확인 후 F |
| F | F01 인계대 / F02 인계대 | 기사·SHP(출하)·유효 PKG(실물 포장 식별자) 확인 | 전체 전달·HOV(기사 인계) 완료 |
| G | G01 상온 / G02 냉장 / G03 냉동 | 파손·결품 조사·품질 회수 검토 | 해제 B/C 또는 처분 H |
| H | H01 반품 / H02 폐기 | 확정된 처분 실행 대기 | RTV(공급사 반품)·DSP(폐기) 실제 결과 반영 |

- 공간이 작으면 B 예비재고 구역은 선택. 입고 후 C 직접 적치 가능.
- E의 예약·즉시 구분은 주문 속성 또는 별도 대기칸으로 관리.
- F 인계대는 장기 보관장소 아님. E에서 필요한 보관조건 유지.
- 센터 간 이송 입고는 TIN(이송 도착) 기준. 공급사 직접 납품이 허용된 경우만 RCV(입고·검수) 사용.
- DC(중앙 물류센터)→PPC(피킹·포장센터) 이송 도착만으로 새 매입 PUR(매입확정)를 생성하지 않음.

```text
DC(중앙 물류센터) → A 도착·검수 → B 예비재고 → C 주문 피킹 → D 포장 → E 온도별 대기 → F 기사 인계
                    └─ 직접 C 적치 가능
이상 → G 격리 → 적합: B/C / 반품·폐기 결정: H
```

## 7. 센터·구역·위치 코드

### 7.1 센터 코드
`센터유형-지역코드-센터순번2자리`

| 예시 | 의미 |
|---|---|
| DC-IC-01 | 인천 지역 DC(중앙 물류센터) 1번 — 설명용 예시 |
| PPC-GN-01 | 강남 지역 PPC(피킹·포장센터) 1번 |
| PPC-GN-02 | 강남 지역 PPC(피킹·포장센터) 2번 |

- 지역코드는 중앙 코드표에서 유일하게 관리. 위 지역 매핑은 설계 예시.
- 순번은 센터유형·지역별 01부터. 폐쇄된 코드 재사용 금지.
- 99개 초과 시 자리수 정책 확장. 기존 코드 일괄 변경 금지.
- 센터 내부 고유 ID 별도 보유. 명칭·주소 변경은 이력 관리.

### 7.2 구역 코드
`센터코드-업무구역문자+세부번호2자리`

- `PPC-GN-01-A02`: 강남 PPC(피킹·포장센터) 1번의 검수구역.
- `DC-IC-01-B02`: 인천 DC(중앙 물류센터) 1번의 냉장 보관구역.
- 세부번호는 센터·업무구역별 등록. 공통 템플릿과 실제 운영 매핑 보존.
- 같은 B02라도 온도는 반드시 속성으로 검증. 코드만 보고 추정 금지.

### 7.3 선반 위치 코드
`센터코드-구역코드-F층2자리-L통로2자리-R랙3자리-S단2자리-B칸2자리`

예: `PPC-GN-01-C02-F01-L03-R007-S02-B04`

| 요소 | 값 | 의미 |
|---|---|---|
| 센터 | PPC-GN-01 | 강남 PPC(피킹·포장센터) 1번 |
| 구역 | C02 | 냉장 피킹구역으로 등록된 구역 |
| 층 | F01 | 1층 |
| 통로 | L03 | 3번 통로 |
| 랙 | R007 | 해당 층·구역·통로의 7번 랙 |
| 단 | S02 | 아래에서 두 번째 선반 |
| 칸 | B04 | 해당 선반의 네 번째 칸 |

- 방향 기준: 평면도에 통로 시작점·랙 정면 지정. 랙 정면에서 좌→우 칸 증가, 단은 아래→위 증가.
- 통로·랙의 번호는 승인된 배치도 기준. 현장에서 임의 순번 발급 금지.
- 새 통로·랙 추가 시 빈 번호 사용. 기존 위치 번호 재정렬 금지.
- 사용하지 않는 번호를 억지로 채우지 않음.
- 상품·Lot·수량·온도·상태는 번호에 넣지 않음.
- 위치는 공간 주소. 보관상품 변경만으로 번호 변경 금지.

### 7.4 바닥·작업대·도크 위치
선반 구조가 없는 곳은 가짜 단·칸 번호를 만들지 않음.

`센터코드-구역코드-F층2자리-위치유형+순번3자리`

| 유형 | 용도 | 예시 |
|---|---|---|
| FL | 바닥·팔레트 구획 | DC-IC-01-A01-F01-FL001 |
| TB | 검수·포장·인계 작업대 | PPC-GN-01-D02-F01-TB003 |
| DK | 상하차 도크 | DC-IC-01-F01-F01-DK002 |
| ST | 출하 대기칸 | PPC-GN-01-E02-F01-ST005 |

- 순번은 센터·구역·층·위치유형별 001부터.
- 냉장 대기칸 ST는 실제 냉장 설비·수용량 확인 후 등록.
- 화면에는 짧은 표시명 제공 가능. 스캔은 전체 코드 또는 내부 location_id로 검증.
- 위치 바코드에는 상품 바코드와 구별되는 위치 식별값 사용.
- TOTE(재사용 운반 용기)·PKG(실물 포장 식별자)·차량·작업자는 위치코드가 아님. 위치와 점유·사용 관계로 연결.

## 8. 업무 일련번호 — 기존 규칙 유지
| 대상 | 번호 | 적용 |
|---|---|---|
| 공급사 입고 | RCV-20261012-000001 | 최초 도착·검수 저장 |
| 내부 이동 | MOV-20261012-000001 | A→B·B→C 등 이동 지시 |
| 센터 이송 | TRF-20261012-000001 | DC(중앙 물류센터)→PPC(피킹·포장센터) 지시 |
| 이송 출발·도착 | TOUT(이송 출발) / TIN(이송 도착) | 출발 건·실제 도착 건별 |
| 출하·기사 인계 | SHP(출하) / HOV(기사 인계) | 고객 출하·인계 단위 |
| 작업·포장 | TSK(작업 식별자) / PKG(실물 포장 식별자) | 작업·실물 포장별 식별 |

- 문서유형·한국시간 생성일별 6자리 순번. DC(중앙 물류센터)·PPC(피킹·포장센터) 포함 전체 센터 공통.
- DC(중앙 물류센터)에서 MOV(센터 내부 이동·적치·보충) 000001 발급 후 PPC(피킹·포장센터)에서 같은 날 다음 MOV(센터 내부 이동·적치·보충) 발급 시 000002.
- 센터별 000001 재시작 금지. 센터·출발·도착 위치는 별도 참조 항목.
- 위치번호의 숫자는 공간 식별값. 날짜별 초기화 금지.
- 동일 요청 ID 재전송은 기존 문서 반환. 실제 새 이동·도착은 새 문서.
- 일일 999999 초과 시 발급 실패·관리자 알림. 자동 순환·중복 발급 금지. 자리수 확장은 별도 버전 정책.

## 9. 위치 마스터·통제
| 속성 | 내용 |
|---|---|
| 식별 | location_id, 전체 코드, 표시명, 센터·구역·층 |
| 구조 | 통로·랙·단·칸 또는 바닥·작업대·대기칸 |
| 역할 | 입고·보관·피킹·포장·대기·인계·격리·처분 |
| 보관 | 허용 온도·상품군·중량·부피·수량 |
| 정책 | 상품·Lot 혼재 여부, 피킹 허용, 입출고 잠금 |
| 운영 | 사용중·중지·폐쇄, 실사 잠금, 적용기간·변경 이력 |

- 역할·온도·용량 변경은 재고·진행 작업 영향 검토 후 적용.
- 격리 위치 이동과 재고 격리 상태 전환을 함께 확인. 위치만 바꿔 품질 상태 누락 금지.
- 정상 구역으로 옮겼다고 자동 격리 해제 금지.
- 실물 위치 변경 시 실제 이동 반영. 마스터 이름 변경으로 재고 이동 대체 금지.
- 선반 재배치로 실제 주소가 바뀌면 새 위치 등록·MOV(센터 내부 이동·적치·보충) 이관·기존 위치 폐쇄.
- 단순 라벨 재출력은 기존 위치번호 유지·출력 이력.
- 위치 폐쇄는 재고 0·진행 작업 없음 확인 후 수행.

## 11. 운영 웹·권한
- 공통 운영 웹 1개. DC(중앙 물류센터)·PPC(피킹·포장센터)별 대시보드·작업 메뉴 제공.
- 동일 시스템의 재고·Lot·실사·품질·이송 규칙 공유.
- PDA(현장 작업 단말)는 스캔 중심 별도 화면. 공급사·고객·기사는 목적별 화면 제공.
- 권한 = 접근센터 × 직무 × 행위 × 배정작업 × 승인조건.
- ID 접두어로 권한 판단 금지. 계정에 권한 속성 연결.

| 사용자 | 기본 메뉴 | 데이터·행위 범위 |
|---|---|---|
| DC(중앙 물류센터) 운영 | 공급사 입고·보관·이송·상차 | 허용 DC(중앙 물류센터)·관련 이송 |
| PPC(피킹·포장센터) 운영 | 이송 입고·재고·주문·피킹·인계 | 허용 PPC(피킹·포장센터)·관련 주문 |
| 본사 운영 | 전체 관제·센터별 예외 | 승인된 복수/전체 센터 |
| 품질 담당 | 격리·재검수·처분 | 승인된 센터·품질행위 |
| 현장 작업자 | 내 작업·스캔·문제보고 | 당일 직무·배정 작업 |

- 센터 변경 시 접근권한·직무 다시 확인.
- 메뉴 숨김과 별개로 서버가 모든 요청의 센터·문서·행위 권한 검증.
- 양센터 이송 담당자는 필요한 상대센터·이송정보만 조회. 상대센터 전체 권한 자동 부여 금지.
- 요청자·승인자·실행자 기록.
- 분리 웹은 독립 운영조직·배포·보안 요구가 생길 때 검토. 별도 웹이어도 문서·재고 연결 규칙 유지.
- 근거: 프로젝트 공통 업무·TRF(센터 간 이송) 연결 구조에 따른 설계 판단. 권한 검증은 [OWASP 지침](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html) 참고.

## 12. 기존 위치코드와 전환
- 기존 `PPC-GN-01-A03-02-01`은 구역·층·통로가 분명하지 않은 이전 예시.
- 새 등록 위치에는 본 문서 형식 적용.
- 기존 데이터가 있다면 문자열로 자동 해석하지 않음. 배치도·현장 확인 후 새 location_id와 매핑.
- 기존 코드는 외부/이전 참조코드로 보존. 기존 거래 이력의 번호 일괄 변경 금지.
- 구·신 라벨 동시 운영 시 양쪽이 동일 위치 ID로 해석되도록 유일 매핑 검증.
- 기존 문서 채번·Lot·실사 정책은 유지. 본 문서는 위치 기준정보 확장안.

5. 용량·혼재·피킹·보관·격리 정책 입력.
6. 위치 라벨 발급·현장 스캔 검증.
7. 센터·직무·행위 권한 설정.
8. 입고→적치→이송→피킹→포장→인계 시나리오 검증.
9. 기존 위치 매핑·전환 승인 후 적용.

## 공개 확인과 구역 제안
- DC(중앙 물류센터)·PPC(피킹·포장센터) 역할·목포 동선·품질 사례는 공개 확인. A~H 문자·코드·물리 구획은 프로젝트 제안.
- MFC(소형 물류센터)는 일반 소형 거점 개념. PPC(피킹·포장센터)와 동일한 내부 운영 코드로 사용하지 않음.
- 무겁거나 고빈도인 상품의 패킹 근접 배치를 PPC(피킹·포장센터) 설계에 반영. 냉장 수축산 지정 위치는 상품 조건별 관리.
- 공통 웹은 프로젝트 선택. 센터별 독립 처리가 사이트 분리를 뜻하는 것은 아님.
