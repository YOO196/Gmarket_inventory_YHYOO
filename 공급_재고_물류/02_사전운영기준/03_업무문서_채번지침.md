### ERP(전사 업무 관리)·WMS(창고·재고 관리) 업무 문서 채번 지침

1. 기본 형식

업무 문서번호는 다음 형식으로 통일한다.

`문서유형-YYYYMMDD-일련번호 6자리`

예: `PO-20261012-000001`

- 문서유형: 업무 종류를 구분하는 접두어
- 날짜: 한국시간 기준 최초 문서 생성일
- 일련번호: 문서유형·날짜별로 000001부터 증가
- 번호 부여 범위: 프로젝트 전체 센터 공통

센터·공급사·상품·수량·상태는 문서번호에 넣지 않고 별도 항목으로 관리한다.

2. 문서 종류

| 업무 | 접두어 | 문서번호 예시 | 생성 기준 |
|---|---|---|---|
| 구매발주 | PO(구매발주) | PO-20261012-000001 | 발주 초안 최초 저장 |
| 공급사 납품예정 | ASN(공급사 납품예정) | ASN-20261012-000001 | 납품예정 최초 저장 |
| 발주 변경 요청 | PCH(발주 변경 요청) | PCH-20261012-000001 | 수량·납기 등 변경 요청 |
| 발주 잔량 취소 | PCN(발주 잔량 취소) | PCN-20261012-000001 | 잔량 취소 요청 |
| 입고·검수 전표 | RCV(입고·검수) | RCV-20261012-000001 | 도착·검수 건 최초 저장 |
| 공급사 반품 | RTV(공급사 반품) | RTV-20261012-000001 | 반품 건 최초 저장 |
| 매입확정 전표 | PUR(매입확정) | PUR-20261012-000001 | 매입 인정 건 최초 저장 |
| 매입 조정 전표 | PJA(매입 조정) | PJA-20261012-000001 | 확정 후 차감·추가 조정 |
| 적치·보충·센터 내부 이동 | MOV(센터 내부 이동·적치·보충) | MOV-20261012-000001 | 위치 이동 지시 생성 |
| 센터 간 이송 | TRF(센터 간 이송) | TRF-20261012-000001 | 센터 이송 지시 생성 |
| 이송 출발 전표 | TOUT(이송 출발) | TOUT-20261012-000001 | 이송 출발 건 생성 |
| 이송 도착 전표 | TIN(이송 도착) | TIN-20261012-000001 | 이송 도착 건 생성 |
| 품질 격리 | QLT(품질 격리) | QLT-20261012-000001 | 격리 건 등록 |
| 폐기 | DSP(폐기) | DSP-20261012-000001 | 폐기 요청 생성 |
| 재고 실사 | CNT(재고 실사) | CNT-20261012-000001 | 실사 문서 생성 |
| 재고 조정 | ADJ(재고 조정) | ADJ-20261012-000001 | 조정 요청 생성 |
| 고객 주문 | ORD(고객 주문) | ORD-20261012-000001 | 주문 최초 저장 |
| 결품·대체 처리 | EXC(결품·대체 처리) | EXC-20261012-000001 | 고객 결정이 필요한 건 생성 |
| 고객 주문 취소 | OCN(고객 주문 취소) | OCN-20261012-000001 | 전체·부분 취소 요청 |
| 출하 | SHP(출하) | SHP-20261012-000001 | 고객 출하 단위 생성 |
| 기사 인계 | HOV(기사 인계) | HOV-20261012-000001 | 출하 인계 건 생성 |
| 환불 | RFD(환불) | RFD-20261012-000001 | 환불 요청 생성 |

문서번호가 부여됐다는 것은 문서가 생성됐다는 뜻이다. 승인·확정·완료 여부는 상태로 판단한다.

폐기 요청·승인·실행은 같은 DSP(폐기) 문서에 기록한다. 입고 검수와 확정도 같은 RCV(입고·검수) 문서의 상태·이력으로 관리한다. 모든 상태 변경마다 새 문서번호를 만들지 않는다.

3. 문서번호와 다른 식별자

| 대상 | 형식 예시 | 관리 방법 |
|---|---|---|
| 작업 | TSK-20261012-000001 | 작업별 번호, 교대 후에도 유지 |
| 포장 | PKG-20261012-000001 | 실물 포장별 고유 번호 |
| 공급사 | SUP-000001 | 기준정보 코드 |
| 센터 | PPC-GN-01 | 센터 기준정보 코드 |
| 위치 | PPC-GN-01-A03-02-01 | 센터·선반·단·칸 기준 코드 |
| 토트 | TOTE-000077 | 재사용 용기 코드 |
| 상품 | SKU-000001 | 상품 기준정보 코드 |
| Lot | 내부 고유 ID + 공급사 Lot값 | 공급사 Lot값만으로 전사 유일성을 판단하지 않음 |
| 스캔·재전송 요청 | UUID(중복 방지용 고유 요청번호) 등 고유 ID | 단말에서 건별 생성, 재전송 시 유지 |

토트는 여러 주문에 순차적으로 재사용할 수 있으므로 주문과 연결한 사용 이력을 남긴다.

포장 라벨의 ‘1/3’은 표시 순번이며 고유 식별자가 아니다. 인계 검증은 PKG(실물 포장 식별자) 번호로 수행한다.

4. 발주·입고 연결 규칙

발주 한 건에 여러 납품예정과 입고 전표를 연결할 수 있다. 문서번호 자체에 상위 발주번호를 넣지 않고 연결 항목으로 저장한다.

예:

| 문서 | 수량 | 연결 |
|---|---:|---|
| PO-20261012-000001 | 90병 | 원발주 |
| ASN-20261012-000001 | 60병 | 해당 PO(구매발주)의 상품행 |
| ASN-20261012-000002 | 30병 | 해당 PO(구매발주)의 상품행 |
| RCV-20261013-000001 | 60병 | 첫 ASN(공급사 납품예정) 및 PO(구매발주) 상품행 |
| RCV-20261015-000001 | 30병 | 두 번째 ASN(공급사 납품예정) 및 PO(구매발주) 상품행 |

문서 안의 상품행은 내부 고유 행 ID와 표시 행번호를 갖는다. 입고·취소·반품·매입은 문서뿐 아니라 대상 상품행까지 연결한다.

5. 변경·이월·취소 규칙

- 발주 변경 후에도 PO(구매발주) 번호를 유지한다.
- 원발주와 이전 버전을 보존하고 변경 요청 PCH(발주 변경 요청)를 연결한다.
- 이월은 기존 PO(구매발주) 잔량의 납품예정을 변경한다. 기존 ASN(공급사 납품예정) 수정이면 번호를 유지하고 변경 이력을 남긴다. 새 납품 차수라면 새 ASN(공급사 납품예정)을 생성한다.
- 잔량 취소는 PCN(발주 잔량 취소)을 연결하고 승인 상태를 기록한다.
- 대체 공급사에 새로 발주하면 새 PO(구매발주)를 생성한다. 기존 PO(구매발주)와 대체 관계를 별도 기록한다.
- 부분 입고가 발생하면 실제 입고 건마다 새 RCV(입고·검수)를 생성한다.
- 문서 변경 버전은 번호와 분리하여 v1, v2 등으로 관리한다.

예: PO(구매발주) 원발주 90병, RCV(입고·검수) 정상 입고 60병, PCN(발주 잔량 취소) 승인 취소 30병을 각각 보존한다. PO(구매발주) 번호를 바꾸거나 원발주를 삭제하지 않는다.

6. 센터 이송 규칙

하나의 TRF(센터 간 이송)에 출발 TOUT(이송 출발)과 도착 TIN(이송 도착)을 연결한다. 부분 도착은 실제 도착 건마다 별도 TIN(이송 도착)을 생성한다.

예: TRF(센터 간 이송) 12병 → TOUT(이송 출발) 12병 → 첫 TIN(이송 도착) 10병 → 잔량 2병 이동 중 → 추가 TIN(이송 도착) 2병.

기존 TIN(이송 도착)의 10을 12로 덮어쓰지 않는다. 입력 오류의 정정은 별도 정정 이력으로 처리한다.

7. 재포장 규칙

포장이 교체되면 새 PKG(실물 포장 식별자) 번호를 생성하고 기존 PKG(실물 포장 식별자)를 무효 처리한다. 이전 포장과 새 포장의 교체 관계를 기록한다.

예: 001·002·003 중 002를 교체하여 004 생성 → 유효 포장은 001·004·003, 총 3개.

동일 포장의 라벨 재출력은 PKG(실물 포장 식별자) 번호를 유지하고 출력 이력을 남긴다. 실제 포장 교체와 단순 재출력을 구분한다.

8. 채번의 중복 방지

일련번호는 서버에서 원자적으로 발급한다. 목록의 가장 큰 번호를 조회한 뒤 1을 더하는 방식으로 구현하지 않는다.

동시 생성·재시도에서도 같은 번호가 중복되지 않도록 문서번호에 유일성 제약을 적용한다.

동일 생성 요청의 재전송은 같은 문서를 반환한다. 새로운 실제 납품·입고 건은 내용이 같더라도 별도 문서를 생성한다. 중복 판단은 상품·수량의 일치 여부가 아니라 요청 고유 ID로 한다.

9. 번호 보존

- 발급한 번호는 수정하거나 다른 문서에 재사용하지 않는다.
- 취소·반려·실패로 번호가 비어도 재채번하거나 뒤 번호를 당기지 않는다.
- 취소·반려 문서는 상태와 이력으로 보존한다.
- 문서 날짜를 수정하거나 소급 처리해도 최초 번호는 유지한다.
- 업무 발생일, 문서 생성일, 승인일, 재고 반영일, 회계 귀속일은 각각 저장한다.

10. 오프라인 처리

오프라인 단말은 UUID(중복 방지용 고유 요청번호)로 임시 기록을 생성한다. 전사 일련번호를 단말에서 임의로 발급하지 않는다.

재연결 후 서버가 문서를 생성하고 정식 번호를 부여한다. 이미 부여된 작업·발주·입고번호는 그대로 참조한다.

동일 임시 기록을 재전송하면 동일 결과를 반환하고 재고·매입을 중복 반영하지 않는다.

11. 전표 확정·정정

문서번호는 식별 기능만 갖는다. 재고·매입 반영은 해당 문서의 확정 상태와 반영 기록으로 관리한다.

확정 전에는 권한에 따라 수정할 수 있다. 확정 후에는 원기록을 보존하고 취소·역처리·정정 또는 조정 전표로 수정한다.

전표번호를 새로 부여했다고 재고가 자동 증가하거나 기존 전표가 자동 취소되도록 구현하지 않는다.

12. 기존 예시 코드 적용

자료의 PO1001·RCV01·TR01 등은 예시 번호로 취급한다.

기존 데이터를 가져오는 경우 내부 고유 ID와 정식 문서번호를 부여하고, 원본 번호는 ‘외부 참조번호’에 보존한다. 외부 참조번호는 공급사·출처 시스템과 함께 관리한다.

W01 같은 화면 코드와 업무 문서번호는 별도 항목으로 관리한다.

13. 센터·위치 기준정보 확장안

센터·구역·층·통로·랙·단·칸과 바닥·작업대·도크의 상세 코드 제안은 [DC·PPC 구역·위치번호 설계안](02_센터_구역_위치번호.md)을 참조한다. 위 위치 예시는 이전 형식으로 보존하며, 신규 위치 등록 형식은 확장안 검토 후 적용한다. 업무 문서번호의 접두어·생성일·전사 공통 순번 규칙은 변경하지 않는다.
