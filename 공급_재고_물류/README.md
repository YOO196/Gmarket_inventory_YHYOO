## 내용의 우선순위
1. 실제 운영 설명은 B마트 공식 사례 우선. 쿠팡은 서비스·센터별 보충 사례.
2. 사용자 채번 정의는 프로젝트 규칙으로 유지. 업체 내부 코드로 표기하지 않음.
3. 원문 요구·화면·예외절차는 프로젝트 구현안으로 정리.
4. 공개 근거 없는 승인선·시간·비율은 미정. 가정으로 실제 규칙을 대체하지 않음.

## 정리한 충돌
| 이전 혼동 | 현재 기준 |
|---|---|
| 모든 센터 입고를 RCV(입고·검수)로 처리 | 공급사 RCV(입고·검수) / DC(중앙 물류센터)→PPC(피킹·포장센터) TIN(이송 도착) |
| 피킹 후 SHP(출하) 생성 | 주문 흐름에서 SHP(출하) 생성·출고 요청 후 피킹 |
| 예약시간 직전만 피킹 | 품질·현장부하에 따른 요청 분산 |
| 이동중·예정 재고를 현물로 합산 | 현물·이동중·예정·예약 구분 |
| 기사 인계 시 차감 고정 | 실제 업체 차감 미확인. 원장 반영 사건 별도 결정 |
| 파손 0%·10만원/100개·3분/5분·0.8 | 근거 없는 기본값 제거·미정 정책으로 전환 |
| 같은 상품 한 위치·Lot 혼재 전면 금지 | 동선·상품조건 배치·Lot 식별·위치 혼재정책 분리 |
| 최소수량 보충 = 이관 자동 할당 | 선반 보충·이관 위치 할당·작업자 배정 구분 |
| 공통 웹 = 업체 실제 웹 구조 | 프로젝트 권고. 센터별 처리 독립성과 별개 |

## 문서 사용
- 파일명 유지. 사용자가 추가한 입점·상품등록 신청, 센터 이점 등 유효 내용 반영.
- 원문 PNG 수정 없음. 기존 필요 조사 항목은 미정 정책으로 유지·현황 보충.
- 도메인 분리는 업무 책임 구분. 서비스·서버 분리는 별도 선택.
- 수정 전 사본은 작업용 백업에 보존. 최신 ZIP은 폴더의 현재 MD로 재생성.
