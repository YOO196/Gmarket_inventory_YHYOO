# 업무 문서 채번과 해운대 MFC 업무 흐름

## 1. 공통 채번

`문서유형-YYYYMMDD-6자리 일련번호`를 유지한다. 날짜는 한국시간 최초 생성일, 순번 범위는 **전사 전체 센터 공통 × 문서유형 × 생성일**이다. 센터코드·위치·상품·수량·상태는 문서번호에 넣지 않는다.

예를 들어 다른 센터가 `MOV-20261015-000136`을 발급한 다음 이 센터의 새 이동이 `MOV-20261015-000137`이 될 수 있다. 이 문서의 번호는 설명용 예시이며 실제 서버 예약·발급 결과가 아니다.

| 업무 | 접두어 | 이 센터 적용 |
|---|---|---|
| 구매발주·납품예정·변경·잔량 취소 | PO / ASN / PCH / PCN | 공급사 직접 납품이 허용된 범위만 |
| 공급사 직접 입고·매입·조정 | RCV / PUR / PJA | 내부 허브 이송에 새 매입 생성 금지 |
| 내부 이동·적치·보충 | MOV | A→B/C, B→C, G 해제 이동 |
| 센터 이송 | TRF / TOUT / TIN | 지시 / 출발 / 실제 도착 연결 |
| 품질 격리·공급사 반품·폐기 | QLT / RTV / DSP | 판정·실제 반출·폐기 분리 |
| 실사·재고 조정 | CNT / ADJ | 원기록 보존·조정 이력 |
| 주문·결품/대체·취소 | ORD / EXC / OCN | 고객 결정·부분 취소 추적 |
| 출하·기사 인계·환불 | SHP / HOV / RFD | 출하 단위와 실제 인계·환불 |
| 작업 식별자·실물 포장 식별자 | TSK / PKG | 문서와 별도 종류, 날짜·전사 공통 순번 |

TOTE는 `TOTE-000077` 같은 재사용 용기 기준코드이며 일별 문서번호가 아니다. Lot는 내부 고유 ID와 공급사 Lot값을 별도로 보관한다.

## 2. 허브 보충 입고와 적치

```text
TRF-20261015-000041 (허브→PPC-BUS-02 지시)
  → TOUT-20261015-000039 (허브 실제 출발)
  → TIN-20261015-000052 (이 센터 A 실제 도착)
  → MOV-20261015-000137 (A03 적치대기→B/C)
```

예: 냉장 상품은 A01-FL002 → A02-TB002 → A03 L02의 냉장 랙에서 확인한다. 적치는 `PPC-BUS-02-A03-F02-L02-R001-S01-B01`에서 `PPC-BUS-02-B02-F02-L01-R001-S01-B01`로 MOV를 연결한다.

실제 도착 수량만 TIN에 반영한다. 120EA 출발·100EA 도착이면 미도착 20EA는 이동 중으로 유지하고, 나중에 도착하면 새 TIN을 생성한다. 원 TIN 100을 120으로 덮어쓰지 않는다. TIN 도착과 품질 판정·판매가능 해제는 별도 상태다.

## 3. 격리와 처분

```text
A/B/C 품질 이상 발견
 → QLT-20261015-000011 격리 등록
 → MOV-20261015-000138 위치 이동, 냉장 G02로 배치
 → 재검수 적합: 승인 후 MOV로 B02/C02 복귀
 → 반품 결정: H01 냉장 L02 랙 대기 → RTV 실제 반출
 → 폐기 결정: H02 냉장 L02 랙 대기 → DSP 승인·실행
```

QLT 판정과 MOV 물리 이동은 연결하되 둘의 역할을 합치지 않는다. DSP 생성·승인만으로 재고를 차감하지 않는다. 같은 DSP에 요청·승인·실행 이력을 기록하고 실제 폐기 확정 시 반영한다. RTV도 실제 반출 결과에 따라 반영한다. 처분이 결정됐어도 H에서 필요한 보관온도를 유지한다.

## 4. 고객 주문·피킹·포장·인계

```text
ORD-20261015-000781
 → TSK-20261015-000452 C01/C02/C03 위치 스캔·피킹
 → D01 검품 → D02 포장
 → PKG-20261015-000881 등 실물 포장 생성
 → SHP-20261015-000642 출하 연결
 → E01/E02/E03 온도별 대기
 → F01/F02 라이더 인계
 → HOV-20261015-000611 전체 유효 PKG 인계 완료
```

주문·상품행·Lot·위치·토트 사용 이력·포장·출하를 별도 참조로 연결한다. 번호 문자열에 상위 문서를 합치지 않는다. 포장 1/3 표시는 고유 ID가 아니며 인계는 실제 PKG로 검증한다.

실물 포장 교체 시 새 PKG와 교체 관계를 남기고 기존 포장은 무효 처리한다. 단순 라벨 재출력은 동일 PKG를 유지한다. 피킹은 재고 위치와 상태 이동이며, 이 설계에서는 실제 HOV 인계 확정 시 출고 차감한다. 중복 스캔·재전송으로 차감을 반복하지 않는다.

## 5. 발급·정정·동시성

- 서버에서 원자적으로 채번하며 `MAX+1`로 발급하지 않는다.
- 문서번호 유일성 제약과 요청 UUID 중복 방지를 적용한다.
- 동일 요청 UUID 재전송은 같은 문서를 반환한다. 새 실제 도착·이동은 새 요청·새 문서다.
- 상태 변경마다 새 번호를 발급하지 않는다. 최초 번호·버전·상태 이력을 보존한다.
- 취소·반려 번호 재사용, 결번 당기기, 센터별 재시작을 금지한다.
- 일일 999999 초과 시 실패·알림 처리하며 자동 순환하지 않는다.
- 생성일·업무 발생일·승인일·재고 반영일을 각각 저장한다. 소급 처리로 번호 날짜를 바꾸지 않는다.
- 오프라인 단말은 UUID 임시 기록만 생성하고 정식 번호는 재연결 후 서버에서 발급한다.
- 확정 후 원기록을 덮어쓰지 않고 정정·역처리·조정으로 연결한다.
